    structure PropertyKindCalculus.ModuleCard.RelationRow :
    Type

    One theorem edge as the card states it: the claim as read from this module (inverts '…', bounded by '…'), the witness, and the optional tolerance and named hypotheses — prepared by the caller from checkRelation's result, so the row is a rendering of a checked edge.

    • claim : String

      The claim, phrased from this module's side.

    • witness : String

      The witness theorem's declaration name.

    • tolerance : String

      The tolerance declaration, where the edge names one.

    • hypotheses : List String

      The named side conditions the claim holds under.

    • other : Lean.Name

      The boundary on the other side of the edge, as a declaration — what the claim string quotes by its rendered name. .anonymous where the row was built without it.

    • witnessName : Lean.Name

      The witness as a declaration — what witness renders.

    • toleranceName : Lean.Name

      The tolerance as a declaration — what tolerance renders; .anonymous where the edge names none.

    • hypothesisNames : List Lean.Name

      The hypotheses as declarations — what hypotheses renders.

        structure PropertyKindCalculus.ModuleCard.ClusterRow :
        Type

        One inter-derivable kind cluster crossing this module's interface: the cluster's representative (the SCC pipeline's name for it) and the module's own kinds that fall in it — prepared by the caller from the kind graph's partition.

        • representative : String

          The cluster's representative kind.

        • kinds : List String

          The kinds of this module's ports that belong to the cluster.

        • refs : List Provenance.KindRef

          The same kinds as references — what kinds renders, kept so a table surface can link each to its declaration. Empty where the row was built without them.

                                    def PropertyKindCalculus.ModuleCard.moduleOverviewCard (c : Provenance.Contract Provenance.NodeId Provenance.KindRef) (relationCount clusterCount : Nat := 0) (notes : List String := []) :
                                    String

                                    The module overview card — the module at first contact, sized for a landscape page. The header carries the caller's notes (a variant tally, a default-binding statement); the interface shows the per-datum inputs and the produced outputs only, side by side; everything else the full sheet carries — parameters, configuration, clauses, theorem edges, clusters — is reduced to one horizontal strip of tally chips deferring to it. Derived from the same checked contract value as moduleCard, and the ports render through the same portGroup, so the overview and the sheet cannot disagree about an interface.
