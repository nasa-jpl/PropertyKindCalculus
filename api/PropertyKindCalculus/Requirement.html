    inductive PropertyKindCalculus.Provenance.RequirementKind :
    Type

    The category of a requirement: how its statement is closed, and so how it is discharged.

    • provable : RequirementKind

      The statement closes over the model's own declarations: a theorem discharges it, and spot checks evaluate it where the model runs.

    • empirical : RequirementKind

      The statement names a referent the model does not define: a gate on an observation discharges it.

            inductive PropertyKindCalculus.Provenance.RequirementScope :
            Type

            The objects a requirement quantifies over.

            • all : RequirementScope

              Every object the governed boundary is evaluated for.

            • sort (sort : Lean.Name) : RequirementScope

              Every object of the named sort — a SortOfSystem declaration, which the objects reach through their Sorted instance.

            • objects (objects : List Lean.Name) : RequirementScope

              The named objects: declarations whose type carries a Sorted instance, so each is an object of some sort and not a bare value.

            • decided (decider : Lean.Name) : RequirementScope

              The objects a named decider selects — a batch's subset, where the objects are carved by a predicate rather than named.

                      structure PropertyKindCalculus.Provenance.Requirement :
                      Type

                      A requirement on a declared boundary: what the boundary's quantities must satisfy, in the author's words, and the evidence by which it is met — the theorem edge or theorem of a provable requirement with its spot checks, the referents and gate of an empirical one, or the attestation that defers either. The prose is not checked and is not meant to be; what is checked is that the governed boundary is a model's, that each named declaration exists and has the shape its field claims, that a provable statement names no referent and an empirical gate names one, that each spot check evaluates to true, and that a claimed absence is absent.

                      • name : String

                        The requirement's identifier, as a document cites it.

                      • statement : String

                        The requirement in the author's words: what must hold, of what.

                      • kind : RequirementKind

                        Provable or empirical.

                      • governs : Lean.Name

                        The declaration name of the model boundary the requirement governs.

                      • port : Option NodeId

                        The governed port of that boundary, or none for everything the boundary produces.

                      • scope : RequirementScope

                        The objects the requirement quantifies over.

                      • witness : Lean.Name

                        Provable: the discharge — a Relation whose left side is the governed boundary and whose right side is a specification boundary, or a sorry-free theorem. Anonymous where the requirement is attested.

                      • spotChecks : List Lean.Name

                        Named Bool declarations the requirement command evaluates and requires true: the runtime spot checks of a proof, at the carrier the model runs on, on operational inputs.

                      • absent : Lean.Name

                        Provable, negative: the declaration of a Prop that is a class application — a license — of which the environment must hold no instance.

                      • referents : List Lean.Name

                        Empirical: the @[kindReferent]-marked declarations the statement names — what the model does not define.

                      • gate : Lean.Name

                        Empirical: the declaration that decides the requirement against its referent — a KindAdmissible instance, a Bool-valued predicate — which must mention one of the referents. Anonymous where the requirement is attested.

                      • attested : String

                        The deferral, in the author's words, where the requirement is not yet discharged. Empty where it is.
